# Skill 九类分类参考

skillify 在 **Round 1** 用这张表给候选 skill 归类。来源：Anthropic《Lessons from building Claude Code: How we use skills》。

## 归一规则

最好的 skill 干净落在**一类**里。横跨 ≥2 类 = 试图做太多，agent 会糊涂——考虑拆成两个 skill，或收窄目标。

判别启发：**这个 skill 的产物/动作，用一句话讲得清吗？** 讲不清，多半是横跨了。

## 九类

| # | 类别 | 一句话定义 | 典型产物 |
|---|---|---|---|
| ① | 库与 API 参考 | 教模型正确用某个库 / CLI / SDK | 代码片段 + gotcha 清单 |
| ② | 产品验证 | 怎么测 / 验证代码真在跑 | 跑流程 + 每步断言 / 录屏 |
| ③ | 数据获取与分析 | 连数据 / 监控栈取数 | 取数脚本 + 字段映射 |
| ④ | 业务流程自动化 | 把重复工作流压成一条命令 | 一条命令产出标准物 |
| ⑤ | 代码脚手架与模板 | 为新功能生成框架骨架 | 新文件 + 自然语言约定 |
| ⑥ | 代码质量与评审 | 强制风格、辅助评审 | lint / 审查 + 可挂 hook |
| ⑦ | CI/CD 与部署 | 拉取 / 推送 / 灰度 / 回滚 | 部署 + 自动收尾 |
| ⑧ | 运维手册（Runbook） | 从症状走多工具排查 | 症状→工具→查询映射 + 报告 |
| ⑨ | 基础设施操作 | 例行维护 / 破坏性操作 + 护栏 | 找→通知→确认→清理 |

## 怎么用这张表

- Round 1 归类后，把"**类别 + 一句话理由**"连同 name/description 一起给用户确认。
- 横跨时**软提示**（"看起来横跨 ⑤+⑥，要不要拆？"），不硬阻断——这只是一个框架，目的是帮你发现"想做太多"的早期信号。
- 边界模糊时，看 skill 的**核心动作**：动作是"生成新文件" → ⑤；动作是"检查既有代码" → ⑥；动作是"跑流程验证" → ②。

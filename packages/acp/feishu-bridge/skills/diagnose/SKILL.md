# 诊断（Diagnose）

报障的纪律：**先建一个只对这个 bug 变红的对证回路，其余一切都是机械劳动。** 没有回路证据的根因结论是猜——读代码读出来的理论、模式匹配已知故障的直觉，都必须经回路验证才能当结论。

## Phase 1：建对证回路

这是本 skill 的全部，后面的阶段都在消费它。回路 = 一条你能命名、**已经跑过至少一次**的命令，它驱动真实故障路径并断言**用户描述的确切症状**——能对这个 bug 变红、修好后变绿。不是「跑起来不报错」，是能抓住这个 bug。

构造法按序尝试，第一个成立的就停：

1. 失败测试（任何 seam：单测/集成/e2e）
2. curl/HTTP 脚本打运行中的服务
3. CLI + fixture 输入，stdout 对拍已知正确快照
4. 无头浏览器脚本断言 DOM/console/network
5. 回放捕获的 trace（网络请求/事件日志存盘后隔离重放）
6. 一次性 harness（最小子系统 + mock 依赖，单函数调用触发路径）
7. fuzz/property 循环（「偶尔错」类 bug 跑 1000 个随机输入）
8. bisect harness（两个已知状态间自动「启动-检查-重复」）
9. 差分对拍（同输入过新旧版本/两份配置，diff 输出）
10. 人工回路（兜底：只有人能做的操作，请用户执行并回报输出）

**本部署已验证的回路配方**：

- zstd 会话日志回放：`zstdcat session.v3.jsonl.zstd` 按事件 seq/time 对证时序（先 glob 会话目录再解压——截断的会话 id 会让 zstdcat 静默输出空）
- mify 代理日志 `api.jsonl` 的 ts/ttft_ms/total_ms 对证——判「活流被杀」看 total 是否远大于 kill 时刻
- 飞书卡 mget 服务端当前内容——分清客户端陈旧渲染与服务端真冻结
- 盲改前 stash 基线对照——大面积测试失败先分清环境性失败与真回归

**把回路当产品打磨**：更快（缓存 setup、砍无关初始化、收窄范围）、更锐（断言具体症状不是「没崩」）、更确定（钉时间、seed RNG、隔离文件系统）。30 秒的 flaky 回路约等于没有；2 秒确定性回路是调试超能力。非确定 bug 的目标是**提高复现率到可调试**——循环触发 100 次、并行、加压、收窄时序窗、注入 sleep；50% 复现率可调试，1% 不可。

**确实建不出回路时明说**：列出试过的构造法，向用户要环境访问、脱敏产物（HAR、日志 dump、带时间戳的录屏）或加临时插桩的许可。**没有回路不进 Phase 2**——发现自己在没有回路的情况下读代码建理论，停：直接跳到假设正是本 skill 防的失败。

## Phase 2：复现 + 最小化

跑回路，看它红。确认红的是**用户描述的那个症状**，不是碰巧在旁边的另一个失败——错的 bug 等于错的修法。然后逐项裁剪：输入、调用方、配置、数据、步骤，**一次删一项、删完重跑**，缩到最小仍红的场景——剩下的每个元素都是承重的（删任一个就变绿）。最小化收窄 Phase 3 的假设空间，也会成为 Phase 5 的回归测试。

## Phase 3：排假设

**先生成 3-5 个假设，再开始测任何一个**——单假设生成会锚死在第一个貌似合理的想法上。每个假设必须可证伪：「若 X 是因，改 Y 应让 bug 消失 / 改 Z 应让它加重」。说不出预测的假设是感觉，丢弃或磨尖。把排好序的清单贴给用户——异步信道里贴完可按自排序继续测，不等；用户常有瞬间重排的领域知识（「我们刚动过 #3」）。

## Phase 4：插桩

每个探针对应 Phase 3 的一个具体预测，**一次只改一个变量**。优先级：调试器/REPL 断点 > 落在区分假设边界上的定向日志 > 永不「全量打日志再 grep」。所有调试日志带唯一前缀（如 `[DEBUG-a4f2]`），收尾一次 grep 清干净。性能回归分支：日志通常是错的工具——先建基线测量（计时 harness、profiler、query plan），再 bisect。先测量后修。

## Phase 5：修 + 回归测试

回归测试写在修之前，但仅当存在**正确的 seam**——测试在调用现场以真实模式触发这个 bug。seam 太浅（单调用方测试测不出多调用方链条触发的 bug）时，回归测试给的是假信心；**没有正确 seam 本身就是发现**——架构在阻止这个 bug 被钉死，记下来上报。有 seam：最小化复现转失败测试 → 看它红 → 修 → 看它绿 → 用 Phase 1 回路对**原始未最小化**场景再跑一遍。

## Phase 6：清理

宣布完成前：原始复现不再复现（重跑 Phase 1 回路）；回归测试过（或 seam 缺席已记录）；`[DEBUG-` 前缀 grep 清零；一次性脚本删除或挪进明确标记的调试目录；**验证为真的那个假设写进提交信息**——下一个调试者要能学到。

## 边界

- 修着修着发现需求本身模糊 → 转 `grill` 做结构化访谈。
- 定位到根因后 → 修复走 `tdd` 的失败测试先行（Phase 1 回路通常就是它）。
- 谈不出来的问题（该做成什么样）→ `prototype` 建最小实验；本 skill 管的是「为什么坏了」。
- 密钥纪律：展示命令与产物前脱敏（`<REDACTED>`）；回路用环境变量持凭证，凭证不进展示；带 auth 头的产物只引携带信号的那几行。

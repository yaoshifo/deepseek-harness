# 结构化访谈（Grill）

需求没想清楚时，把访谈做在动手前，而不是返工后。访谈的目标不是收集信息凑数，是把决定逼出来：结束时每条决定都能一句话说清，用户能对每个选择讲出为什么。

## 何时烤、何时不烤

烤：用户一句话提了件要做的事（功能、方案、报告、策划、选型都算）；同一请求存在几种实质不同的做法；用户在构思、比较方案、思考出声。

不烤：歧义不实质影响工作——挑合理的解读继续并说明选了哪个。能自己查清的疑问不属于访谈内容（见下）。已拍板过的决定不重开，除非新信息推翻它。

## 协议

1. **自查先行**。能从代码、仓库、文档、记忆里查到的，直接查，不问用户。问用户是最后手段，不是第一步。
2. **按轮提问**。一轮 = 一次 `ask_user_question` 调用，装下**当前所有能问的独立问题**——即前置决定都已落定的问题；每问附 2-4 个选项并标 `recommended`。依赖本轮答案的问题留到下一轮，绝不提前问。一轮以 5 问为经验上限——超过通常说明范围太大，先建议拆分任务，或先问最能砍掉大片分支的那一问。多问题在飞书上逐题投递：一题一张卡，答完自动出下一题，不是一屏勾完。
3. **谈不出来的别硬谈**。手感、样式取舍、性能够不够、第三方实际行为——这类问题做出来才知道，反复换措辞问只会让范围膨胀。指出它谈不出来，用 \`prototype\` skill 建最小实验，等结果回来用一句话回答。
4. **攻最弱假设**。问题按「哪个假设错了会崩掉最多东西」排序，先问最弱的那环。不为凑轮次穷举低风险问题。
5. **终止与汇总**。设计树遍历完、没有隐含假设时停。汇总每条决定——一句话加为什么——然后开工；plan 模式会话里把决定写进计划的白话层。用户对某条回答「不知道」是真实答案，通常意味着该转第 3 条。

## 反模式

- 问前置决定还没落地的问题（「X 场景下怎么办」而 X 本身还没定）。
- 问能自己查到的（入口在哪、现状什么行为、谁在调用）。
- 对着谈不出来的问题反复换措辞——访谈膨胀的头号来源。
- 穷举低风险问题，回避最弱假设。
- 访谈完不汇总就开工，决定散落在问答里没人能复述。
- 被动接受用户回答里的矛盾；发现矛盾当场指出再问。

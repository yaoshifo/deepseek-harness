# Agent Note: 追问卡推荐标注与 multi_select 引导

Status: implemented

[English](2026-09-17-ask-card-recommended-tag-and-multiselect-hint.md) | 中文

## 问题

一次线上追问（会话 cc-20260917-090512，群 oc_1c55，2026-09-17；会话日志的 `tool/call` 行即证据）暴露两个模型行为缺口：

1. 问题文本明说可多选（「想真正把采集节奏拉到 10 秒级，你要哪条？（可多选，比如并发化 + 缩小范围一起）」），但调用未携带 `multi_select`（两种键名拼法都没有；该 question 的键只有 `header`/`id`/`options`/`question`）。缺省为 false，卡片按单选渲染，用户无法在卡上同时选两项。
2. 那张单选卡上推荐信号只有按钮 primary 高亮，模型只好自己往推荐项 label 里写「（推荐）」补偿——标不标注全凭模型自觉。

## 决定

1. `tool-ask-user` 的 `multi_select` 字段描述补引导：问题文本告知用户可多选时必须显式传 true，否则卡片渲染为单选。`recommended` 字段描述写明 UI 会标注推荐项、禁止把标注写进 label。
2. 单选卡推荐项渲染双信号：primary 按钮（原有）+ label 上的本地化推荐后缀（新增 `ask_recommended_suffix` 词条，五语言）。多选卡与 followups 卡不加标注——预勾选已是完整的行动级信号。定格快照不加：`settledOptionMarks` 与派发的选择消息共用，回读数据面绝不能携带渲染专用标注。
3. 双叠防护：label 不含词条表任一标准词形（任意位置）时才追加后缀，比对前先经 `foldTagForm` 折叠——统一小写、各类括号（全/半角、方括号、【】）折成 ASCII 对应括号、去除全部空白——半角、方括号、大小写、带空格的变体因此全部比对相等。检测集合直接从 `messages.ask_recommended_suffix` 派生——单一事实源；注册子表不能覆盖主表键，静态派生与渲染值必然同源。两类失误都落在安全侧：漏判只是该项缺文字信号（高亮仍在），绝不会双叠。
4. `extra.askq_label` 与答案 `selected` 恒为原始 label——模型回读的数据面不带标注。

## 备选方案

- **只改描述、不动渲染：让模型自己写标注。** 否决：把结构化 `recommended` 字段降级回自由文本约定——正是要修的「凭自觉」病根——且模型写的标注会流进 wire 面 label 与答案。
- **查重用 `endsWith` 结尾匹配。** 否决：label 中间的标注（复合选项「X（推荐）+ Y」）漏判后双叠；`includes` 覆盖该形态，漏判后果也只是显示不足。
- **裸词「推荐」入检测集合。** 否决：「不推荐」选项含其子串，会被误判为已带标注。

## 后果

所得：单选卡推荐项获得「高亮 + 本地化标注」的确定性双信号，不再依赖模型自觉补写；「可多选」文案与卡形态的错配在模型恰好漏传的那个字段上有了契约层引导。代价：推荐项文字渲染变长几个字符（窄卡上该行可能换行）；工具描述每会话多约 50 tokens；查重只认带括号的标注形态（比对前已折叠大小写、空白与括号字形）——裸词无括号形态（「推荐：X」、名为「不推荐」的选项）与 markdown 强调式标注在显示上仍会双叠（数据面两种情况下都保持原文）。

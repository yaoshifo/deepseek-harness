# Agent Note：diagnose 与 prototype skill —— 报障先诊断命令与 grill 的实验逃生门

状态：已实现

[English](2026-09-15-feishu-bridge-diagnose-prototype-skills.md) | 中文

## 问题

两个缺口，均系 grill 落地后拍板补齐：

1. **bug 调查没有方法论。** TDD 默认段原本明确豁免调查阶段（「之前的调查阶段不受此约束」），根因定位全靠模型裸判断。三次在案误诊同属一个失败形状——没有能对该 bug 变红的回路就下结论：watchdog 盲杀活流（total_ms 远大于 kill 时刻）、09-10「无 thinking 签名」误诊至 09-14 才改判（签名查错了位置）、FB-Eval 把 status 误读成 reasonKind。
2. **grill 的逃生门下面没有地板。** grill 协议把谈不出来的问题（手感、样式取舍、性能、第三方行为）路由到「最小实验」，但实验怎么建、什么纪律保证它是一次性的、验证过的决定怎么折回，都没有定义。

## 决定

沿用 tdd/grill 的两层模式，带一个刻意变化：

- **诊断命令并入现有 TDD 默认段而非新建节。** 报障与修复是同一个生命周期；该段本来就为普通会话与 subtask 子会话双注册（子任务常收 bug 调查任务书），命令天然继承两个分支，零新增注册。这也遵守 08-28 的常驻克制教训：不建第四个常驻节。新增约 150 字符：报障时先加载 `diagnose` 建只对该 bug 变红的对证回路、无回路证据不下根因结论、回路通常就是后续那个失败测试。已失真的豁免句（「之前的调查阶段不受此约束」）随之删除——调查阶段现在是受约束的那段。
- **`skills/diagnose/SKILL.md`** 承载六阶段回路，自 aihero 的 `diagnosing-bugs` 适配：建回路（十种构造法按优先级排序，第一个成立的就停）→复现与最小化（一次删一项、删完重跑、只留承重元素）→3-5 个可证伪假设排序（贴出但不阻塞——异步信道）→插桩（一次一个变量、`[DEBUG-` 标签日志、性能分支先建基线测量再 bisect）→修加正确 seam 上的回归测试（无 seam 本身就是发现）→清理（回路重跑、标签 grep 清零、验证为真的假设写进提交信息）。本部署已验证的回路配方是一等公民：zstd 会话日志回放、mify api.jsonl 的 ts/ttft/total 对证、飞书卡 mget 服务端终态对证、盲改前 stash 基线对照。aihero 的 hitl 脚本模板不搬——飞书信道里的人工步骤就是一条请你操作后回报的消息。
- **`skills/prototype/SKILL.md`** 仅按需加载，无常驻节：grill 已路由到它。六条护栏（day-one 标记 throwaway、一条命令可跑、默认无持久化、跳过打磨、每个动作后摆全量状态、验证过的决定折回后删除原型——原型代码绝不迁移，只迁移结论），两个分支（逻辑原型=单文件可分享 HTML 驱动状态机，经 html skill 直投聊天；UI 原型=一页多个激进变体，仅 web 项目）。grill 协议第 3 条改为指名本 skill。
- 边界三角，三个 skill 内互相写明：grill 管需求模糊、diagnose 管「为什么坏了」、prototype 管「该是什么手感」；交接显式（diagnose 修出需求模糊→grill，定位到根因→tdd，prototype 答案回来→grill 汇总/tdd 实现）。

## 备选方案

**单独的 diagnose 默认节（order 15/25）。** 否决：与 TDD 默认段生命周期连续；第四个常驻节让每个普通会话为 TDD 节已覆盖的触发多付注意力。

**逐字移植 aihero（含命名）。** 否决：其 CONTEXT.md/ADR 指针、hitl bash 模板与终端交互假设都需按本部署改写；本部署已验证的配方（会话日志回放、api.jsonl 对证）才是原版没有的本地价值。

**扩展 triage runbook 代替。** 否决：feishu-session-log-triage 是飞书故障指纹手册；diagnose 是任意报障的通用方法论。二者互引配方，但各管一层。

## 后果

普通会话与 subtask 子会话的 TDD 默认段约 500 字符（原约 360）。目录新增两个条目；三个工作风格 skill 构成边界显式的三角。grill 的按轮批问裁定不受影响。

复测（reload 满一周，与 grill note 同款扫描法）：报障会话应在首个根因结论之前建起回路（三次误诊形状即负基线）；谈不出来的问题应路由到 prototype 而非反复换措辞；清晰需求保持不触发 grill。适用 08-28 方法论（先 glob 会话目录再 `zstdcat`）。

# Agent Note: Machine wakes steer into a busy parent turn

Status: implemented

English | [中文](2026-08-27-feishu-bridge-machine-wake-steer.zh.md)

## Problem

The 2026-08-27 oc_56801302 incident: a parent chat spawned six native subtasks inside a turn that then ran for 40+ minutes without calling `gather` — the designed escape path ("the escape is not calling gather, which keeps the per-report incremental wake", [2026-08-27](2026-08-27-feishu-bridge-blocking-gather-and-failure-settlement.md)). That path's busy-parent leg had never been built: every child report re-entered `receiveMessageSafe` as a synthetic `[子任务完成]` message, hit the session lock, and joined the **human** message queue. The user saw six unexplained 📬 queued-notice replies (one per report), the sixth report was silently dropped at `maxQueuedMessages=5`, and all five queued copies lived only in memory. Worse, one child had reported through the runtime's native `report` tool, whose delivery splices straight into the runtime parent inbox — the engine cannot observe that channel, so `subagent/end` settlement delivered the same content a second time. Two adjacent defects surfaced during triage: the live card's "N 个子任务后台运行中" hint was written once at spawn and only recounted at turn end (the parent agent, reading the stale footer plus a bare `[ready]` tag, narrated "子任务都还在跑（ready/排队态）" — `ready` in fact means archived and resumable), and `adapter.followupChild` passed no `signal`, so every `send` to a settled child crashed on the runtime cold-resume arm's `options.signal.throwIfAborted()` — two environment-hint follow-ups to W2 were lost that way.

## Decision

Keep the B4 architecture — external settlement, engine-owned delivery, the blocking gather's banking — and finish the designed escape path instead of replacing it:

- **`deliverMachineMessage` seam** (engine): machine messages (child report wakes, gather-summary wakes, chatroom moderator wakes, follow-up injections) reach a **busy** parent turn mid-turn via `AgentSession.steer` — claimed at the next step boundary, so several wakes batch into one step — and fall back to the existing synthetic-message pipeline for an idle parent (which needs the full turn machinery), the startup window, or a busy-but-dead agent session. The platform message queue is human-only by construction after migrating every synthetic injector (engine, chatroom, chatroom-cmd; cron stays on the pipeline by design — its mode override, workDir switch, and new-session-per-run semantics need the full message path). The chatroom `[主持]` ask keeps the pipeline too: its `chatroomAskSeq` metadata is consumed at turn start for gather-round pairing, and a mid-turn steer would skip the stamp.
- **Single reporting surface**: the bundle patch disables `tool-subagent-report`. Its `report` tool delivers into the runtime parent inbox, a channel the engine cannot observe — the double-delivery source. `feishu_bridge_subtask` action=report is the only reporting surface (the child persona already says so); the `subagents` service's `reportFrom` path remains for native-parent delivery. A `toolFilter.deny` cannot name the tool: it registers per child, not globally, and `restrict` validates against the global registry — composition is the enforcement point.
- **Footer freshness**: `refreshSubtaskFooter` recomputes `pendingNativeChildrenOf` and PATCHes the live-card hint whenever a child's `reported` flag flips (report, settlement, interrupt), mirroring the turn-end recount's background-task interplay.
- **`followupChild` signal**: pass `AbortSignal.timeout(startContinuableTimeoutMs)`, matching `reportChildToNativeParent`; the runtime's cold-resume arm requires it.
- **`list_agents` legend**: every non-empty render appends a one-line status legend so a bare `[ready]` cannot be misread as queued-and-running.

## Alternatives considered

- **Skip the synthetic wake when the parent is busy** ("the runtime splice already delivered"): rejected — only a child that called the native `report` tool gets a runtime splice; a bridge-tool report or a settlement has no other delivery vehicle, so skipping loses the report. Steer delivers mid-turn instead.
- **Return delivery to the runtime (`settlementNotice: 'inbox'`)**: rejected after red-teaming. It reverses B4's channel split and collides with the fresh blocking-gather design in four places: the runtime cannot suppress notices while a gather waiter is armed (the summary-as-tool-result property — one model request for spawn → gather → synthesize — depends on banking); the 2026-08-27 note already rejected both re-enabling the native `subagent` tool and feeding native children into unsolicited-reader keep-alive (the counter drifts against gather's N-to-1 banking); `subtaskQuiet`'s wake-only semantics would reshuffle; and the freshly pinned gather/settlement test surface would be rewritten. Runtime-woken idle turns also depend on the unsolicited reader, whose budgets were tuned through incidents. The engine keeping delivery preserves every one of those decisions.
- **Deny the native `report` tool via `toolFilter`**: rejected mechanically — the tool is child-scoped, so `tools.restrict` cannot name it; the bundle patch is the working enforcement point.

## Consequences

- Machine wakes to a busy turn arrive mid-turn (faster than queue-then-drain), batch at step boundaries, are durable session events (steer splices log as inbox events), and can no longer hit the queue cap or be lost to a daemon restart. The queue's 📬 notice, 5-message cap, and in-memory storage now bind human messages only (README Known Limitations records the restart-loss caveat and the cron carve-out).
- The number of concurrent subtasks is uncapped everywhere (runtime, gather expected set, steer batching); the incident's "5" was the human queue leaking onto machine traffic, not a subtask limit. `maxDepth` (default 3) caps nesting depth only.
- Existing persisted children created before this change may still hold the native `report` tool in their descriptors; a pre-change child that calls it double-delivers exactly as before until it is drained. New children never see the tool.
- Tests: `deliverMachineMessage` three states plus footer refresh in `engine-subtask.spec.ts`; the followup-signal regression in `tests/agent-dsh/adapter-followup-signal.spec.ts`; the list-agents legend in `tool-subagent-control`. The blocking-gather three-state, settlement-vocabulary, and REAL-composition cases pass unchanged — they are the regression proof that this change completes rather than reverses the 2026-08-27 design.

# Agent Note：grill 访谈命令 —— 面向模糊需求的常驻节 + 按需 skill

状态：已实现

[English](2026-09-15-feishu-bridge-grill-conventions.md) | 中文

## 问题

结构化访谈约定（「需求模糊或设计空间较大时，先做结构化访谈再动手」——一次只问一个、每问附推荐答案、能查先查）自 6 月起一直住在机器本地的全局指令里（`~/.claude/CLAUDE.md`，提交 `9e1753a`「add grill」，2026-06-22），但在桥接会话中执行不到位。三层叠加的原因：

1. **送达**：全局用户指令以用户消息内 `<system-reminder>` 的形式搭载，是指令预算超限时第一个被丢的段（已知的渲染顺序缺陷，用户裁定等上游修）。
2. **决策时刻失忆**：桥自己的常驻约定里住着同一条规则的弱化版——「提一个聚焦的问题，否则挑合理解读继续」——在会话开工那一刻把完整版挤了出去。这与 [2026-08-28 TDD 命令回归](../process/2026-08-28-tdd-mandate-tier-regression.zh.md)实测的是同一种「可见≠执行」失效（66%→14%）：常驻文本压倒非常驻文本。
3. **感知**：触发条件「需求模糊」是元判断——模型要先承认请求是模糊的，而这恰恰是会失败的判断。

## 决定

复刻 TDD 的两层模式——常驻命令式节扛命令，按需 skill 扛协议：

- `### 需求模糊先访谈（grill）` 加入 `agentConventionsPrompt()`（仅普通会话，order 10；子任务子会话拿到的任务书已由父会话拍板，聊天室人设整体替换系统提示词）。节内不写抽象元规则，写可对号入座的触发信号——一句话要动手做的事（功能、方案、报告、策划、选型都算）、同一请求存在几种实质不同的做法、用户在构思或比较方案——外加内联降级纪律（能从仓库查到的先查；一轮一张追问卡装下当前所有能问的独立问题、每问附推荐答案；谈不出来的问题转最小实验）与不触发边界（歧义不实质影响工作→挑合理解读继续并说明）。「异步自主」第一条 bullet 改为指向本节，实质歧义规则从此只有一个家。节内刻意不写 `ask_user_question`：`followups.spec.ts` 钉死 conventions 提示词不得出现通用问答工具名，保证收尾卡继续走 `feishu_bridge_followups`。
- `skills/grill/SKILL.md` 按需承载完整协议，同时是用户可显式调用的入口（「grill」「烤一下这个想法」）：先查后问；一轮一次 `ask_user_question` 装下所有当前能问的独立问题（单卡经验上限 5 问——超过通常该拆任务，或先问最能砍掉分支的那一问）；依赖答案的问题留到下一轮；谈不出来的问题（手感、样式取舍、性能、第三方行为）转最小 prototype/实验而非反复换措辞；攻最弱假设而非穷举低风险问题；设计树遍历完、无隐含假设即终止——每条决定一句话加为什么，plan 模式会话把决定折进计划的白话层。
- CLAUDE.md 该行从 dotfiles 仓库删除，沿 `12ceaa3` 先例；08-28 判例已否决机器本地命令（新机器部署缺口）。

**协议裁定（用户，2026-09-15）：按轮批问取代 2026-06-22 的一次一问校准。** 6 月那条规则是为交互式终端使用校准的（「多问会让人懵」）；异步飞书信道里每个来回以小时计，而追问卡原生支持一卡多问、每问带选项和推荐勾选——一轮一张 frontier 卡把一场访谈从几天压到一两轮。防懵的守卫从「逐条问」换成「依赖排序」（绝不问前置未定的问题）。

## 备选方案

**只加常驻节（不建 skill）。** 否决：没有用户可显式调用的入口，协议深度与反模式清单没有家；节必须保持精简。

**只建 skill（不加节）。** 否决：这正是 2026-08-24 的错误——目录描述在决策时刻不可靠触发（TDD 实测 66%→14% 崩塌）。

**强化或恢复 CLAUDE.md 行。** 否决，依据 08-28 判例：指令预算丢弃顺序 + 机器本地部署缺口。

**机制化触发（monitor 式轻量旁路调用对入站消息分类，检测到模糊即注入命令）。** 搁置：唯一能从架构上修「感知」层的方案，但在常驻节效果实测之前不建机制；作为复测不达标时的升级路径。

**逐字采用 aihero 的 grill-me skill。** 否决：6 月的 CLAUDE.md 行已是同一方法论的手工内化版；缺失的三个概念（frontier 依赖排序、ungrillable/prototype 边界、终止判据）折进了桥内 skill。

## 后果

普通会话的常驻承载为：conventions 节（约 1450 字符）+ TDD 默认（约 360）+ grill 节（约 370）。子任务子会话与聊天室人设两者皆无——与 skillify 提议同一分层；dsh web 会话不在覆盖内，与 TDD 命令同一已接受取舍。

与 TDD 的无条件触发（实现→循环）不同，grill 靠感知触发；具体化触发信号是缓解手段，剩余折扣已在案。多问题访谈卡是新的运行时路径：ask 工具入参本就是问题数组，followups 的 ask 委托特判只认单问「后续处理」签名，访谈卡正常停车等待——首次实际使用时冒烟验证渲染。

复测判据（reload 满一周）：抽样一句话请求的会话（功能或非代码交付物），看 grill skill 加载与开工前的追问卡（基线里沉默开干之处应出现这两者）；抽样需求明确的会话看误触发（应≈0）。适用 08-28 扫描方法论（先 glob 会话目录再 `zstdcat`；reload 前的会话全部是基线）。

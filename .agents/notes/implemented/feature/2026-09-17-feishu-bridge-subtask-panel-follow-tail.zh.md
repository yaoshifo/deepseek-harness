# Agent Note: 子任务实时面板被顶离尾部时在聊天底部重发

Status: implemented

[English](2026-09-17-feishu-bridge-subtask-panel-follow-tail.md) | 中文

## Problem

后台子任务实时面板在回合带着未回报原生子任务落定时发布一次，此后原地 PATCH——而原地更新永远不会移动消息位置。其后聊天里发出的一切都落在它下面：本回合自己的 ✅ 完成卡、回复 HTML 渲染图、追问建议卡、每次子任务回报唤醒回合的新进度卡、群头像更新系统消息。这些消息逐个夺走「最新消息」的会话摘要，飞书会话列表预览因此不再显示「后台子任务 · N 个运行中」——面板的存在意义就是承载这个状态，而它却只有点开聊天才能读到。

用户的第一直觉是压制发送方（面板存活期间不发通知卡、不发回复图）。这只有在「机器发起的一切都静默」时才成立，而静默必须覆盖逐个回报的唤醒回合——代价正落在这里：父 agent 无法再对每个子任务的回报即时反应。

## Decision

面板跟随尾部，而不是让聊天静音：**当平台的活动账本显示面板卡下面落了更新的已记账消息时，面板重发**——在聊天尾部发一张携带当前内容的新卡、删除被顶开的旧卡、改持新句柄。不压制任何东西；父 agent 对回报的即时反应完整保留；面板把会话摘要赢回来。

两个触发点共用一条重发路径：

- **刷新 tick**（`refreshSubtaskPanel`，每 `subtaskLivePanelIntervalMs`，默认 15s）：探针门控——仅当位移探针（`PreviewDisplacementProber`，即流式预览位移自愈所骑的同一账本）报告卡片被顶开时才重发。这为引擎不拥有的所有顶开源（人类消息、其他发送）兜住收回延迟。
- **回合收尾**（`reclaimSubtaskPanelTail`，由 `handleResultEvent` 在 phase 重绘之后调用）：刻意不走探针。回合的占位卡经 `sendPreviewStart` 发送，后者被活动账本有意豁免——卡的重发不能顶开自己——因此在没有逐回合 ✅ 的项目（`notifyOnComplete: false`）上，探针看不见坐在面板下面的那张已定稿回合卡。强制收回补上这个盲区；在发 ✅ 的项目上冷却窗吸收它的冗余。

围绕跳动的纪律：

- **冷却**：每 `previewReissueCooldownMs`（2s）至多一次重发尝试，发起时刻即记标记，竞态刷新无法双发。
- **内容让位于位置的反面——位置让位于内容**：重发失败回退为对仍存活旧卡的原地 PATCH（同一份渲染内容；流式预览位移自愈的同款纪律）——尾部重试在途时面板绝不陈旧。
- **终态不跳**：done/drained 转换永远原地 PATCH；窗口已结束，综合回复拥有尾部。
- **降级**：无位移探针或无删卡能力的平台保持纯 PATCH（跟随底部之前的行为）；删除失败只孤儿化旧卡（warn 日志）。
- **与流式预览无乒乓**：预览卡发送豁免于账本，运行中回合的卡在回合期间拥有尾部、面板不与它争——回合收尾时面板收回。面板自己的重发确实会记账，但预览的自愈只在其内容 flush 时触发，因此每条真实消息至多多出一轮有界交换。

配置：`features.subtaskLivePanelFollowTail`（默认开），经 `setSubtaskPanelConfig` 下发。

## Alternatives considered

- **用面板武装的 gather 屏障攒集回报，全部子任务汇报后一次性唤醒父**（首个获批方案）。用户复核后否决：它以推迟父对每个回报的渐进反应为代价换取「面板必然保持最后」——提前处理与追问要等最慢的子任务或 gather 超时。跟随底部以零反应代价达成同一预览目标。
- **窗口期内压制回合收尾的发送（✅ 卡、回复图、追问卡）。** 否决：丢用量统计与渲染投递，且唤醒回合的进度卡照样顶开面板——单靠压制永远到不了目标。
- **静默唤醒回合**（不发占位卡、中间反应走 NO_REPLY 约定）。否决：中间工具活动不可见，「面板保持最后」依赖模型 NO_REPLY 纪律而非机制，且进度卡机制需要自建暗模式。
- **每 tick 无条件重发。** 否决：账本探针已让位移驱动的重发足够，每 tick 一跳纯属churn——只在真有消息越过卡片时才跳。

## Consequences

- 窗口期内每次被顶开多付一条消息（尾部新面板卡 + 删旧卡）——会话列表未读数略涨；飞书里看到面板「跳」到底部。这是拥有会话摘要的既定代价。
- 窗口期内面板也跟到人类消息下面——用户在场时无害（尾部正是他读的位置），且自愈：活动停歇后面板持有尾部。
- 唤醒回合运行期间，回合卡拥有尾部（它就是最新信息）；面板在该回合收尾时收回，延迟以 tick 冷却为界。
- 重发要求卡句柄能被平台位移探针与删卡能力接受（飞书 `sendCardWithHandle` 返回的 `FeishuPreviewHandle` 符合）；其他平台静默降级为纯 PATCH。
- live 部署零配置改动（默认开）；按项目用 `features.subtaskLivePanelFollowTail: false` 关闭。
- 测试：`tests/engine/subtask-panel.spec.ts` 的 `panel follow-tail reclaim` describe 钉住被顶重发与后续原地 PATCH、终态不跳、配置关闭、冷却、强制收回及其 no-op、两种失败回退。

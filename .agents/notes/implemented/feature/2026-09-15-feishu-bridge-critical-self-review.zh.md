# Agent Note：结论前批判性自检作为常驻门

状态：已实现

[English](2026-09-15-feishu-bridge-critical-self-review.md) | 中文

## 问题

结论级产出（计划、技术选型、根因结论、性能建议）带着没挣来的确定性就发了出去。四步批判性自检规则一直住在机器本地的全局指令里——正是 grill 与 TDD 命令逃离的那条用户消息提醒通道：预算超限第一个被丢，决策时刻被挤出。证据：09-10「无 thinking 签名」误诊站了四天到 09-14 才改判；FB-Eval 把 status 误读成 reasonKind；以及当天的一个活案例——本部署落地对话里提出的第一版 prototype 触发词修法过宽（会误抓纯演示请求），是被用户的钢人抓住的，不是被模型自己的自检抓住的。

## 决定

`agentConventionsPrompt()` 新增第七个常驻节 `### 结论前自检`（仅普通会话），置于 grill 节之后，补齐决策质量三角：grill 在决定前攻问题，diagnose 的 Phase 3（可证伪假设排序）是 bug 侧的实例，本节在交付前攻答案。四步——自我批判（未验证假设、隐藏依赖、最薄弱环节）、钢人法（最强反对论点，不是稻草人）、红队（哪个假设错了崩掉最多；pre-mortem：6 个月后若失败最可能因为什么）、结论（站得住就交付并附已识别风险，否则换方案或明标不确定性）——带比例规则（简单场景：推荐后一段风险；重要决策：展开四步）与豁免清单（事实查询、代码解释、机械操作）。「默认怀疑第一个方案」与「先质疑用户前提」折入。

「白话直讲」节的发计划前自检改为引用四步而非复述（一事一家）：先过可读性，再过四步自检，风险写进计划。

**不建 skill**——刻意为之。tdd/grill/diagnose 需要按需正文，是因为其程序性深度（循环、访谈协议、六阶段）超出一句常驻行；四步本身约 240 字符，常驻装得下。这是 08-28 常驻克制教训的反向应用：内容紧凑时，仅常驻才是对的。

CLAUDE.md 该节从 dotfiles 仓库删除（grill / `12ceaa3` 先例）。

仅普通会话的作用域：subtask 子会话不带本节——它们的回报经父会话呈现，结论级产出在父会话的综合处成形、门也设在那里。已接受的缺口：单个子会话的错误中间结论依靠父会话的自检与子任务任务书约定兜底，而非逐子会话设门；若观察到子会话侧失灵，扩展进 subtask 前导是升级路径。

## 备选方案

**单独的自检 skill。** 否决：内容紧凑；为一句常驻段花一个目录条目不值，且仅 skill 的部署丢决策时刻召回（08-24 崩塌）。

**并入 TDD 默认段（subtask 子会话也注册）。** 否决：四步放在实现纪律节里离题，且给每个子会话的中间产出都设门会让回审成本翻倍，而父会话本就要综合它们。

**扩展 bundle patch 的 plan-mode 引导。** 否决：该文本与 dsh-base 保持 lockstep，fork 本地改动会打架上游同步。

## 后果

conventions 节增至约 2100 字符；普通会话携带七节加 TDD 默认段。计划到达审批前应既过可读性又过四步（风险呈现在细节层）；带建议的回复应带风险段或明确的四步痕迹。复测（一周，同款扫描法）：基线里裸结论之处，带建议的回复与提交的计划应出现风险段/自检痕迹。

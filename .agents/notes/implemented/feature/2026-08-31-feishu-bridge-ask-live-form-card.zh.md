# Agent Note: feishu-bridge 问题卡是带每题文字通道的活表单

Status: implemented

[English](2026-08-31-feishu-bridge-ask-live-form-card.md) | 中文

## Problem

合并多题的问答卡（[B2](../simplification/2026-08-24-feishu-bridge-ask-delegate.zh.md)）只有一条自由文字通道：聊天文字，且永远路由到第一道未答题。线上实锤（2026-08-31，运维群）：用户点了第 1 题的选项后，一句本意补充第 1 题的说明——「直接复用 记账驴 不再新建」——被绑成了第 2 题的 custom 答案，因为第 1 题已答、路由只会向后落。

同一根因还有三个缺陷：

- 没有改答案通道。已答题在换卡时冻结（按钮消失），平台回调对已答题的再次点击直接丢弃（注释却承诺会更新），聊天文字也无法指向已答题。
- ask 结算后的旧卡点击会把原始 `askq:N:M` 载荷当普通消息漏给模型当下一轮 prompt。
- 卡面唯一的教学是一句「也可以直接文字输入」，从不说清文字会答到哪一题。

## Decision

卡片在结算前是活表单。

- **每道未结算的题保持可交互并显示当前答案**：单选行保留按钮、上方加 `当前：` 行，多选 checker 保留提交、当前选择打勾，卡内文字答案显示为 `✍️ 文本`。全部答完后换卡为只读终态——冻结标记、custom 文本、无控件、标题追加 `· 已全部作答`。
- **每题自带文字通道**：输入框（`askq_text_{q}`）+ form_submit「✍️ 文字作答」按钮（`askq_text_submit_{q}`），无选项的题也有——输入框是它唯一的卡内作答路径。wire 格式新增 `askq_text:{q}`，且任意载荷可在 NUL 分隔符后随带文字（`askq:{q}:{idx}\x00{text}`）——与 `perm:` 裁决 note 同一约定。`parseAskqSelection` 先按 NUL 切分再解析序号，答案文本里的冒号不会破坏 wire 格式；`resolveAskAnswer` 允许 `custom` 与 `selected` 并存——上游 user-questions 类型本就允许这一对。
- **聊天文字可显式选题**：多题 ask 上 `N: 答案` 前缀绑定（并修订）第 N 题。半角冒号后必须跟空白，`2:30` 因此仍是普通答案；全角冒号允许无空白，贴合输入法习惯。越界前缀按普通文本处理。✅ 回显带 `（n/total）` 进度，且当还有其他题开放时附选题教学（`Msg.AskqTextAddressHint`）。
- **改答放行、重试吞掉**：平台去重只吞完全相同的重复（双击/回调重试）；变化的答案更新记录并重新派发，引擎按题覆盖——同题最后写入者胜。
- **旧卡点击被消费**：无停放 ask 的 askq 卡片动作回 `AskqStaleQuestion` 提示，不再泄漏载荷。

## Alternatives considered

**回退到每题一张卡**（B2 之前的 Go 行为）。同时发 N 张卡不改变「第一未答题」路由歧义——只有顺序游标变体（答完当前题才发下一张）能消除它，而那要重写 `routeQuestionResponse` 加两套行为规格套件（`engine-m3-askq`、`card-action`）。比活表单工作量大，且一次 ask 刷 N 张卡。

**显式「完成作答」提交门**（最大改答窗口）。否决：它给每次 ask 强加一步提交——包括本就工作良好的单题多数场景——用户忘记提交时回合永久挂起；普通会话的 ask 没有超时兜底（只有 chatroom research-manual 有 10 分钟默认值）。活表单 + 自动提交 + 下一轮消息纠错以零额外步骤覆盖同样场景。

**去掉「第一未答题」回退、强制显式选题。** 否决：单题 ask 今天能用好恰恰因为普通聊天文字就能作答；收尾追问约定（`agent-conventions.ts`）依赖无前缀自由文字承载「按新任务理解」的指令。

## Consequences

- 卡片形状可观察地变化：每道交互题带文字输入表单，已答未结算题显示当前答案而非冻结，结算卡只读并带 `· 已全部作答`。
- 聊天文字答案会同步回卡面：引擎把已收集状态推给有卡平台（`syncAskCard`，与 `sendCard` 同样的鸭子类型探测），平台将其并入回调侧 `askqAnswered` map 并 PATCH 发送时记录的 ask 卡——无回调也能保持活表单/终态渲染的真实性，后续点击的换卡保留已同步状态。卡片动作跳过同步（其回调响应本就换卡）；记录或缓存缺失、PATCH 失败都是记日志的 no-op，绝不破坏答案路由。
- 飞书按每次回调响应重建卡片，因此按下卡上任意按钮都会丢弃其他题输入框里的草稿。输入框按题隔离，影响面是一题的草稿；已接受的答案在卡面自身回显。
- 接受的残余歧义：无前缀聊天答案恰好以 `N:` 开头（半角冒号加空白，或全角冒号）时会绑定第 N 题；纯数字答案仍表示选项序号。结算后的修正走普通下一轮消息——ask 工具已经返回。
- `AskCardAnswered` 值从 `number[]` 加宽为 `{ indices, custom? }`；chatroom 消费方只读引擎侧 answers map，不受影响。
- 空提交——`askq_text_submit_{q}` 输入为空，或多选提交既无勾选也无文字——以 fire-and-forget 聊天提示拒绝（「请先在输入框填写文字…」/「请至少勾选一项…」）；既不派发也不搅动卡片。

# Agent Note：单选问题卡移除卡面文字输入——文字作答统一走聊天框

状态：已实现

[English](2026-09-16-feishu-bridge-askq-single-select-no-text-input.md) | 中文

## 问题

单选问题卡上，选项按钮和文字输入表单是两条互不相通的提交通道：选项按钮渲染为表单外的列表行，点击无法携带输入框里的草稿。由此产生两个面向用户的歧义：

1. 推荐选项渲染为 primary（高亮）按钮，被读成「已预选」——在输入框打字后点「文字作答」，感觉会提交「推荐项 + 文字」。实际只提交了文字。
2. 先打草稿再点选项按钮，感觉两者都会提交。实际只提交选项；草稿留在输入框里，不会发送。

多选卡与收尾建议卡的表单内备注一直是勾选的补充；单选卡是唯一例外，这个不一致正是两种误读的温床。

## 决定

有选项的单选问题不再渲染卡面文字输入表单（输入框 +「文字作答」提交按钮）。收尾提示 note 改为指向聊天：「不选选项？直接在聊天里发消息回答」。聊天自由文本本就是现成作答路径（resolveAskAnswer 的 custom 分支；多问题 ask 支持「题号: 答案」寻址），卡片不再自带文字通道。

无选项问题保留文字输入表单——它是该卡唯一的卡面作答路径，且没有选项可与之组合，输入框不携带歧义。

「先选选项、再补文字」不做原生支持：提交答案后紧跟着的聊天消息会被理解为补充（模型在相邻上下文里同时看到两者）；残余的时序竞争——答案结算后 agent 立即继续，慢一步的补充落进下一轮——是聊天的自然节奏，不是缺陷。选项经常需要补充说明的问题是提问设计问题，用更好的选项或无选项提问来修，而不是在交互层打补丁。

## 备选方案

**把选项按钮收进同一个表单，让点击携带输入框草稿**（全卡种统一「文字 = 补充」）。否决：四文件连锁（卡片渲染、回调解析、卡片元数据提取、i18n）、与存量并存的全新回调解码路径、飞书卡片 schema 上未经生产验证的表单内列表行布局、外加真机冒烟门——都为了一个非主流场景。

**两步提交**（勾选表单 + 提交按钮，对齐多选形态）。否决：丢掉常见场景下「点一下即答」的快捷性。

**纯文案缓解**（更锋利的占位符与按钮文案，行为不变）。否决：草稿被静默丢弃的问题依旧，治标不治本。

## 后果

- `askq_text:` 回调处理保留——无选项卡与本次改动前发出的卡片仍在使用；用户聊天里改版前的单选卡照常工作，行为不变。
- `askq_text_placeholder_options` 文案词条删除（只有带选项卡片在用）；`askq_text_placeholder`（「输入你的答案」）此后只服务无选项表单。
- 单选与多选卡片形态维持差异，但语义无冲突：文字只出现在多选卡上且恒为补充；单选卡完全不携带文字。
- 点选项后发出的文字补充落在下一轮（上述时序竞争），属设计内行为。

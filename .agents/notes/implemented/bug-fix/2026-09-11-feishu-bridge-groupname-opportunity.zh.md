# Agent Note: 群名重命名机会绑定到会话标签，直到有消息为群命名

Status: implemented

[English](2026-09-11-feishu-bridge-groupname-opportunity.md) | 中文

## Problem

2026-09-11，群 `oc_823de9…` 由一次 idle `/spawn`（不带任务参数）创建，占位名为「运维虾 副本」。用户的第一条消息是「hi」，被含糊种子 guard 拒绝（2 个 rune < `minGroupNameSeedRunes` 4），自动改名因此跳过——这一步本身正确：该种子不含任务。但触发条件只对「会话窗口还没有任何轮次」的群成立（`recentTurnsOf(…, 1).length > 0` 提前返回），于是之后的每条消息——包括随后的 429 排查——都进不了命名路径。群名永久停留在占位名。同一形状在数小时前已经命中过 `oc_a08f239d…`，其首条消息同样是「hi」。

2026-09-03 的含糊种子 guard（[one-shot forks](2026-09-03-feishu-bridge-oneshot-fork-workdir.zh.md)）跳过一句光秃秃的「继续」是对的：用它命名会让模型凭环境上下文编出主题。缺陷在于，跳过同时也消耗掉了唯一的命名机会。

## Decision

- 命名机会绑定到标签，而不是绑定到「第一条消息」。只要聊天的会话标签仍是 spawn 占位名——`/spawn` 与 subtask 群为 `<bot> 副本`，`/fork` 为 `<bot> 分支`——`handleSpawnedGroupFirstMessage` 就会改名。含糊种子只跳过自己，下一条有内容的消息仍可为群命名；标签已带名字（自动或手动改名而来）的聊天永不重入该路径。guard 本身不变。
- 占位名只有一个定义：`groupname.ts` 中的 `spawnPlaceholderName` / `isSpawnPlaceholderName`，由三个创建点（/spawn、/fork、subtask spawn）与判定共用，生成的标签与识别的标签无法漂移分家。
- 卡片回执不参与命名：权限裁决、追问卡选项、收尾追问选择携带的是按钮文案而不是任务文本，触发面放宽后它们会把按钮文字变成群名。
- 每个聊天同一时刻只有一个命名查询（`groupNamingInFlight`）：30 秒查询窗口内接连到来的有内容消息，不得启动并发改名导致群名被翻两次。
- 改名落地后引擎自己同步会话标签（`handleChatRenamed`），而不是等平台的 rename 事件，使占位名判定不会在事件延迟窗口内触发第二次改名。

## Alternatives considered

- **保留「跳过即终结」，只把它变可见（日志，或群里提示）。** 可见并不给群一个名字；用户仍要手动 `/rename`，而 idle spawn 的默认结局依旧是占位名。
- **让含糊种子进入 LLM。** 这正是 2026-09-03 事故修掉的行为：种子里没有任务时，模型会从环境上下文编一个，比没有名字更糟。
- **把「已命名」做成新的持久状态（spawn store 标记或会话字段）。** 老聊天没有该标记，其「未命名」语义必须回填——而唯一忠实的回填依据就是标签本身。标签才是权威；标记会是可能漂移的第二份拷贝。
- **从平台读取群名，而不是用会话标签。** 平台读取需要新增公开方法，而且改名路径仍需要标签同步以避免竞态。会话标签已经持久化、已经由 rename 事件更新，也已经是 spawn 路径写入的那个值。

## Consequences

- 测试：`engine-groupname.spec.ts` 锁定新机会（占位名标签 + 非空会话窗口下，有内容的消息触发改名）、已命名群回归、卡片回执过滤、in-flight 守卫、标签同步，以及占位名判定的精确匹配。chatroom 的 spawn 流程对照组现在会把标签设为占位名，与 spawn 路径的产物一致。
- 部署：host 构建加一次手动 `/reload`；活体信号是 `/spawn` 不带任务 → 「hi」→ 一条有内容的消息，随后 daemon 日志出现 `chat renamed`。报障的那个群（`oc_823de9…`）会在它的下一条有内容消息上自愈。
- 已知边界：判定以会话标签为键，因此占位名群里执行 `/new`（标签被重置为空）会停止自动命名，直到有一次改名落地；bot 改名会让更早的占位名失配，判定随之保守拒绝；一句有内容但并非任务的消息仍可能起一次名——仍好过永久占位名。
- 非 LLM 命名路径（`groupNameEnabled` 关闭）共享同一触发条件：关掉 LLM 命名时它会直接用当前消息命名，直到成功一次。两个线上部署都开着 LLM 命名；关闭路径由 chatroom 套件的对应用例覆盖。

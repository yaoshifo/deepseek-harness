# Agent Note: feishu-bridge × chatroom scan round two — batch A/B fixes

Status: implemented

English | [中文](2026-08-30-feishu-bridge-scan2-fixes.zh.md)

## Problem

The 2026-08-30 second-round six-way parallel read-only scan (dispatch/spawn subsystem, session state machine, render pipeline, platform IO, chatroom full package, assembly/tool surface) produced 43 findings. This batch fixes the 6 high-severity items and 12 mechanical medium/low items, each test-first (a failing reproduction test turned red for the right reason before the fix landed). Policy findings (session-record growth, drain-turn reaping, cron timeout/overlap guards, workDir threading, modeOverride, Map LRU, deadline-race cancellation, triage serialization) stay open for a decision.

## Decision

**H1 — tenant-token staleness self-heal failed at three chained points.** (1) `isTenantAccessTokenInvalid` scanned only err.message while SDK verbs carry 99991663 in the AxiosError body (`response.data.code` — the shape fix from the 230020 repair was never migrated to the token classifier), and the token-retry tests all faked the text shape the real SDK never produces — green tests, dead production path. (2) `fetchFreshTenantAccessToken` read the minter cache, so the "fresh" token could be the just-rejected one. (3) `disableTokenCache` was never actually passed, and the SDK's formatPayload overwrites the Authorization header set by `withTenantToken` with its own cached token. Fix: the classifier reads `feishuBusinessCode` (already in the same module) plus the invalid-access-token text fallback; the minter gains `invalidate()` (`TenantTokenMinter`) and the stale refresh invalidates before re-minting; the Client is really constructed with `disableTokenCache: true` and every verb carries the minter token explicitly (`tokened(opts)` merge, explicit Authorization wins) — the minter becomes the single token authority. Fake-shape tests now use the SDK's real AxiosError shape. **The dead 230011 (reply target withdrawn) fallback is the same root and fixed the same way** (feishuBusinessCode equality), so a withdrawn trigger no longer loses the turn's final answer.

**H2 — chatroom machine wakes were claimed as the human's answer.** In a serial roundtable, after a role calls ask-human, its own end-of-turn relay wake enters through `deliverMachineMessage` and hits the route-human-reply waterfall (no origin discrimination): the moderator never receives the wake, the pending flag is cleared by the role's own message, and the role is fed "human answer: [its own words]". Fix: a `Message.machine` flag set on the idle delivery path, carried in the waterfall payload, and the chatroom listener passes machine messages through (returns false → the normal agent path).

**H3 — a residual appendText timer downgraded the progress card to plain text.** The throttle timer callback ignored progressMode; under the common text→tool ordering it PATCHed status-less content, wiping the tool section, todos, and live header. Fix, belt and braces: a progressMode guard in the timer body plus `cancelTimerLocked()` when appendProgress/appendThinking arm progressMode.

**H4 — four-backtick fences were split mid-run.** Pass 1 scanned per character and inserted a newline inside a ```` run; pass 2 toggled fences on any 0-column ``` inside a code block. Fix: pass 1 walks whole backtick runs (break before a run ≥3 mid-line only); pass 2 is length-aware (a pure-backtick line at least as long as the opener closes). The table heuristics share the same semantics via `FenceTracker`: pipe lines inside fences are code text and are never collapsed (the old test pinning "fenced tables still count" was a porting simplification and changed with the behavior).

**H5 — /dir card actions bypassed admin_from.** commandGate ran only on the text dispatch path; handleCardAction ran dirApply directly while the /help card's system page links /dir. Fix: the card path calls the same `commandGate?.('dir', p, msg)` slot (engines without registered commands keep the text path's pass-through).

**H6 — the monitor poll watermark advanced only over processable messages.** The platform filtered (bot's own / sender-less without fallback_user / no text) before returning, so a full page of unprocessable webhook-card storm messages pinned the watermark and buried every later alert. Fix: the interface becomes `MonitorPollPage { messages, latestTimeSec }` — latestTimeSec covers every fetched raw item including filtered ones, and the watermark always advances.

**Batch B (mechanical).** The streaming-preview text path gained `sanitizeFeishuMarkdownHTML` unconditionally (containsMarkdown does not count bare HTML tags, so pure-HTML text escaped entirely into 11311 triple-failure degradation); the tool-progress ring buffer renders from `progressWriteIdx` (oldest slot) so wraparound keeps timestamps ordered and 🚨 on the last line; the bare-HTTP verbs (getBotInfo/getMessage) pass `AbortSignal.timeout(retryTiming.requestTimeout)` (a black-hole connection no longer pins WS startup for ~25 minutes); the lark-cli tool declares `timeoutMs: 300_000`, threads `exec.signal` into the child and the TAT mint fetch, and caps `--page-limit` at 200 pages; the assembly fails loud on duplicate project names (they silently shared state/sessions files and cross-wired lark-cli credentials); `ProjectStateStore.load` validates shape (null/array/primitive JSON falls back to empty state instead of crashing the first accessor at plugin load); a free-text answer carrying attachments stages them (no longer silently dropped); an out-of-range askq payload (a stale card naming a question that no longer exists) is consumed with a stale hint instead of queueing the raw `askq:5:1` into the model prompt; the failed-start placeholder state calls `beginTurn()` (pairs with the caller's finally endTurn; activeTurns no longer goes negative); `ChatNameCache` does not cache transient network failures (`isTransientError` gate; only deterministic misses eat the 1h fail TTL).

## Alternatives considered

**H1: pass disableTokenCache only, without per-verb tokens.** Rejected: with the cache disabled the SDK injects no Authorization at all — normal requests would go out bare and 401. Explicit per-verb tokens from the minter (cache hit costs no network) satisfy both "normal requests carry a token" and "refreshed tokens actually take effect".

**H6: advance the watermark by the newest filtered message.** Rejected: a fully-filtered page has no messages to advance from — the watermark must come from the raw fetched items.

**A compatibility shim for the listMonitorMessages shape.** Rejected: pre-release stance (root AGENTS.md) — change the shape outright and update the platform implementation, engine consumer, and test doubles together.

## Consequences

An early-revoked token now self-heals in one retry instead of muting the bot for up to ~2h (indefinitely with clock skew); a withdrawn reply target no longer loses the turn answer; the serial ask-human roundtable path works (the moderator receives wakes; human answers route correctly); nested code examples survive both preview and final cards; the progress card no longer degrades on residual timers, ring-buffer timestamps read monotonically, and fenced pipe lines are no longer collapsed; non-admin members cannot reach /dir through the help card; an alert storm no longer buries later alerts; bare-HTML previews no longer trip 11311 degradation; black-hole connections no longer pin startup; lark-cli calls are bounded and cancellable; duplicate project names fail loud at load; a corrupted state file no longer crashes plugin startup.

Still open (policy items awaiting a decision): session-record growth (TTL vs ring), drain turns reaped by the idle collector, cron timeout cancellation + overlap guards, cron workDir global switching, modeOverride silently dropped, unbounded Maps in platform.ts (LRU trade-off), the 30s deadline race not cancelling in-flight requests, triage capacity TOCTOU, send/lark full file-system access, /list delete-mode gating.
